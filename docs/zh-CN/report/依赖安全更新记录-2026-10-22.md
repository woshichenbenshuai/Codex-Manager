# 依赖安全更新记录（2026-10-22）

## 范围

本轮只修改依赖清单、自动生成的锁文件、Node 构建环境、Docker 构建上下文排除规则和文档。不修改业务源码、账户/TOTP 流程、数据库、网关选路、界面或 Compose 的 `17000:48761` 映射；不删除已有测试。

项目的正式容器是 Rust 服务加静态前端，Node 只用于构建。没有 LiteLLM、aiohttp 或 Go 运行依赖，不能把其他生态的通告直接认定为本项目漏洞。仓库可选 Python 代理脚本及宿主机另装的软件需独立检查。

## 保留告警与边界

本记录不宣称整个项目依赖树“零漏洞”，也未使用忽略列表隐藏扫描结果。

- **前端开发工具**：`eslint-config-next -> @next/eslint-plugin-next -> fast-glob -> micromatch -> braces@3.0.3` 仍报告 `GHSA-vfj7-8cjw-p6xm`（high），查询时无官方修复版本。它不在最终 Rust 容器运行，但构建/开发环境风险仍需保留；不为消除告警强制覆盖不兼容依赖。
- **仅锁文件中的可选 QUIC**：`quinn-proto` 有告警，但 Linux 正常依赖树未启用它。保留记录，不把未构建组件等同于实际请求入口漏洞。
- **服务器仍需关注的依赖**：`smartstring` 为停止维护提示；`webbrowser@0.8.15` 的 Unix `BROWSER` 参数注入修复需要升级到 1.2.2 以上；`zip@2.4.2` 的批量提取 API 告警需要 9.x 才有官方修复。后两项涉及跨大版本兼容，不在本轮强制升级。
- **ZIP 使用核对**：服务器技能导入自行逐条校验路径、拒绝符号链接并屏蔽特权权限位，未直接调用通告中的 `ZipArchive::extract()` / `ZipStreamReader::extract()`。这只解释本次通告的适用性，不代表所有归档处理都已证明安全。桌面更新器另有自写解压逻辑，需单独复审。
- **桌面依赖另行处理**：桌面锁文件仍有 `anyhow`、`glib`、`quick-xml`、`rkyv`、`serde_with`、`tauri`、`zvariant`/`zbus_names`、旧 `rand@0.7` 等安全/不健全告警，以及 `fxhash`、`proc-macro-error`、`unic-*` 等维护提示。它们不属于用户当前 Docker 镜像的 Tauri 运行链，未以服务器补丁名义顺带升级桌面框架。

## 部署要求与来源

现有服务器需要重新构建镜像，不是只停止/启动旧容器。操作见 [运行与部署指南](运行与部署指南.md#从源码更新现有服务器)。保留 `.env`、数据目录和原 TOTP 加密密钥，不增加端口、不直接暴露内部服务端口。这里仅提供部署说明，不自动操作服务器。
